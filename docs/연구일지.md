##  1. v2 평가
### KoMT Bench
- LG AI research에서 개발한 평가 지표로, EXAONE을 평가하기 위해 LLM의 멀티턴 능력과 지시 이행 능력을 평가하기 위해 설계된 MT-Bench를 한국어로 번역한 버전이다.
- 글쓰기, 역할극, 추론, 수학, 코딩, 추출, STEM, 인문 8개 분야에 각 10개씩 총 80개 질문으로 구성되어 있다.
- gpt-4o가 답변의 퀄리티(도움이 되는 답변인지, 질문과 관련 있는지, 정확한지, 깊이가 있는지, 창의성이 있는지, 자세한지)와 수식의 정확성, 언어 드리프트의 유무를 판단하여 1~10점까지의 점수를 매긴다.
- 기존엔 2턴에 걸쳐서 평가를 했으나, 프롬프트 모델은 1턴의 질문만 수정하기 때문에 1턴까지의 대화만을 보고 평가한다.
- 추론 모델은 qwen2.5-3B, qwen2.5-7B, qwen2.5-14B을 사용하였다.
#### 유의성 검정
- 세 점수 차이 모두 p-value 0.000~0.002로 점수가 유의하게 나빠졌다. 신뢰구간 또한 모두 0을 포함하지 않았다.
- p-value는 윌콕슨 부호 순위를 양측검정으로 하였고, 신뢰구간은 부트스트랩으로 도출하였다.
- p-value는 차이가 얼마나 유의한지 보여주며, 신뢰구간은 차이가 얼마나 큰지를 알려준다.
- 윌콕슨 부호 순위 검정은 표본이 작거나, 짝지은 차이가 정규분포를 따른다고 보기 어려울 때 사용하는 비모수 검정 방법이다.
- 각 관측값 쌍(같은 질문에 대한 점수)의 차이를 구한다. 차이가 0인 데이터는 보통 제거하지만, 본 연구에서는 제거하지 않고 순위 합을 양수와 음수에 반씩 나누었다 (zsplit).
- 차이에 절댓값을 씌워 작은 순으로 순위를 매기고 (같은 값은 평균 순위), 부호를 복원한다.
- 이후 양수 순위의 합과 음수 순위의 합을 구하여 더 작은 값을 검정 통계량으로 사용한다 (표본이 충분히 크거나 동점이 있으면 정규분포로 근사하며, 그렇지 않을 경우 고유한 분포를 사용한다. 본 연구의 KoMT 점수는 동점이 많아 정규분포 근사를 사용했다).
- 이와 별도로 신뢰구간은 80개의 차이를 복원 추출하여 평균을 구하는 과정을 1만 번 반복하는 부트스트랩으로 계산하여 95% 신뢰구간을 추출하였다.
### Reward Model (Skywork-Reward-V2-Qwen3-4B)
- 싱가포르 Skywork AI에서 발표한 오픈소스 모델이다.
- 본래 강화학습 단계에서 AI 모델이 출력한 답변의 품질을 평가하기 위해 만들어진 모델이다.
- Skywork-Reward-V2-Qwen3-4B는 질문과 답변으로 구성된 대화뭉치를 입력으로 받으면 LLM의 출력에 대한 평가점수를 출력으로 출력하도록 학습되었다. 
- 점수 분포에는 제한이 없으나 대개 -10점~10점 사이의 점수를 반환한다.
- 해당 모델은 학습 과정에서 방대한 양의 human preference 데이터를 반영한 것으로 알려져 있기 때문에, 인간의 답변 선호도를 잘 반영했다고 평가받는다.
- 해당 평가에서는 원래질문과 원래질문을 통과한 답변의 쌍, 원래질문과 최적화된 질문을 통과한 답변의 쌍에 대해 점수를 측정하였다.  
- 추론 모델은 qwen2.5-3B, qwen2.5-7B, qwen2.5-14B을 사용하였다.
- 데이터는 v2 학습 데이터 1031개에서 54개의 테스트 데이터세트의 질문과, KoMT Bench에 사용한 80개 질문 데이터를 사용하였다.
#### 유의성 검정
- p-value는 윌콕슨 부호 순위를 양측검정으로, 신뢰구간은 부트스트랩으로 도출하였다.
- 두 데이터 모든 경우에서 p-value 0.000~0.001로 명확한 성능저하가 발생했고, 신뢰구간 또한 0을 포함하지 않았다. 
#### 평가 결과 (KoMT)
- 원문 프롬프트를 통과한 답변의 점수 평균은 3B, 7B, 14B 순으로 5.20, 6.64, 7.71이었다.
- v2 프롬프트를 통과한 답변의 점수 평균은 3B, 7B, 14B 순으로 3.96, 5.51, 6.02이었다.
- 원문 프롬프트 대비 v2 프롬프트 답변의 점수 차이 평균은 3B, 7B, 14B 순으로 -1.24, -1.13, -1.69였다.
#### 평가 결과 (Reward Model)
- 답변의 승률과 점수 차이를 함께 보았다.
- 54개의 테스트 데이터에서 원문 프롬프트 대비 v2 프롬프트의 점수 차이 평균은 3B, 7B, 14B 순으로 -1.89, -2.19, -1.95였다.
- 54개의 테스트 데이터에서 원문 프롬프트 대비 v2 프롬프트의 승률은 3B, 7B, 14B 순으로 28%, 28%, 19%였다.
- 80개의 KoMT 벤치마크 데이터에서 원문 프롬프트 대비 v2 프롬프트의 점수 차이 평균은 3B, 7B, 14B 순으로 -3.00, -3.19, -3.87였다.
- 80개의 KoMT 벤치마크 데이터에서 원문 프롬프트 대비 v2 프롬프트의 승률은 3B, 7B, 14B 순으로 24%, 19%, 19%였다.

## 2. 데이터 개선
### 섹션 제거 실험
- v2 답변의 구조는 [역할], [과제유형], [수행단계], [출력형식] 섹션으로 이루어졌으나 각각 어떤 섹션에서 성능저하가 발생했는지 명확하게 확인하였다.
- v2의 학습 데이터 1031개에서 54개의 검증 데이터세트의 질문 (테스트 x)을 qwen2.5-7B로 추론하였고, 채점은 Skywork-Reward-V2-Qwen3-4B을 사용하였다.
- [출력형식] 삭제 : v2 대비 0.99점 증가 (p = 0.05)
- [역할] 삭제 :  v2 대비 0.01점 증가 (p = 0.894)
- [수행단계] 삭제 : v2 대비 0.54점 감소 (p = 0.373)
- '분량: ' 삭제 : v2 대비 0.31점 증가 (p = 0.172)
- '{빈칸}' 삭제 : v2 대비 0.20점 증가 (p = 0.730)
- [원래요청] 추가 : v2 대비 0.86점 증가 (p = 0.06)
- 원문과도 비교를 했으나 원문보다 승률이 모두 낮았으며 점수차 또한 신뢰구간이 0을 포함하지 않아 유의하게 나빴다.
- [출력형식]과 [역할] 섹션을 제거하고, [원래요청]을 뒤에 추가해야 한다는 근거를 얻었으나, 그럼에도 불구하고 원문보다 성적이 좋게 나오지 않았다.

### 구조화 실험
- 이 실험에서는 v2가 사용한 데이터 세트 자체의 치명적인 허점과 새롭게 구조화된 포맷을 찾기 위해 설계되었다.
- v2의 학습 데이터 1031개에서 54개의 검증 데이터세트의 질문 (테스트 x)을 qwen2.5-3B,7B,14B로 추론하였고, 채점은 Skywork-Reward-V2-Qwen3-4B을 사용하였다.
- 각 질문 별로 여러 버전의 프롬프트를 통과시킨 후에 원문 대비 점수 차이가 얼마나 발생하는지를 측정하였다.

- C와 D는 gpt-4o으로 증강하였다. 특히 C의 경우 v2의 섹션 중 유의마하다고 판단되는 것만 끼워넣으라고 지시하였고, 섹션 제거 실험의 결과를 반여하였다.
- A를 보면 알 수 있듯 v2는 최적의 결과로 학습되더라도, 유의미한 개선이 발생하지 않는다.
- C에서 gpt-4o가 역할과 빈칸을 제거하고, 출력 형식에서 분량 같은 불필요한 제약을 없애며, 맨 뒤에 원래요청을 추가하고, 증강이 필요한 질문에만 증강을 하니 실제 성능이 유의미하게 향상되었다.
- 결론적으로 v3에서는 역할과 빈칸 빼기, 지어내지 않기, 원문을 끝에 그대로 보존하기 조건을 지킨 데이터를 학습하고, 특히 특정 섹션에 대해 증강이 필요한지와 같은 능력 또한 학습해야한다는 것을 알 수 있다.

## 3. v3 학습
### 데이터 구축
- gpt-4o-mini가 v3 형식([과제 유형] + [과제] [맥락 및 가정] [수행 단계] [출력 형식] + [원래 요청])의 정답을 생성한다. 
- 과제 유형과 원래 요청은 rule-based로 원문을 보존하였고, 구조화가 도움이 되지 않는 수학, 추출, 추론 과제는 증강하지 않고 [과제 유형] 기타만 삽입하여 패스하는 형식으로 생성하였다.
- 이후 [출력 형식] 제거 유무 능력을 학습시키고 원문보다 확실히 나은 프롬프트만 남기기 위해 해당 섹션을 추가한 버전과 추가하지 않은 버전의 답을 skywork 보상 모델로 채점하여 점수가 더 나은 결과만 남기게 하였다.
- 결과적으로 구조화된 답변 654개, 패스 103개, 검증 54개, 테스트 54개를 남겼고, [출력 형식]이 제거된 데이터는 전체에서 패스 포함 457개였다.

## 4. v3 평가
### WildChat300
- 기존의 평가에서 사용되었던 KoMT Bench 80이나 테스트용 54개 데이터는 표본 수가 매우 적어 통계적 유의성을 확보하는 것이 어렵다.
- 따라서 실제 한국어 사용자들의 채팅 데이터인 WildChat으로부터 짧고 모호한 질문 300개만 따로 검수하여 평가에 활용하였다.
- 또한 보상모델 뿐만 아니라 GPT-4o-mini를 판정자로 사용하여 어떤 답변이 더 나은지 판정만 하고 점수는 이겼을 때 1, 비겼을 때 0.5, 졌을 때 0으로 환산하였다.
- KoMT 또한 벤치마크의 프롬프트가 이미 길고 자세하기 때문에 이 연구의 취지와 맞지 않다고 판단하여 제외했다. 
### IFEval-Ko
- LLM이 사용자의 명시적이고 구체적인 지시사항을 얼마나 잘 따르는지 평가하기 위한 벤치마크이다.
- rule-based로 작성한 코드이기 때문에 judge 모델을 사용하지 않는다.

## 4. v4 학습
- 모델의 방향을 '구조화된 프롬프트 생성'에서 '원문으로부터 적절한 방향(헤더) 확장'으로 바로잡았다.
- 실제 대화 상황에 맞는 문장을 학습한 LM의 특성에 맞게 프롬프트를 온전한 한 문단으로 생성하도록 데이터를 바로잡았다.
### 데이터 구축
- v3의 학습 데이터로 사용한 질문에 짧은 요청 512개를 추가로 생성했다. 이때, 평가 지표에 사용되는 데이터와 유사한 데이터는 제외하였다.
- 요청에서 답이 상황에 따라 갈리는 지점을 명시하고, 해당 요청에서 다룰 내용 2~4개를 확장하라고 지시했다.
- 요약할 글이 없는 요약이거나 정답이 하나인 요청은 확장없이 그대로 유지했으며, 코드 작성과 개념 관련된 질문은 다시 쓰도록 규칙으로 고정하였다.
- 비용, 일정, 최신 정보처럼 지어낼 위험이 큰 요청 또한 그대로 유지하였다.
- 이후 gpt-4o-mini가 하나의 문단으로 이어서 재작성하였으며, 말투를 원문과 최대한 유지하도록 하였다.

### v3 학습 데이터의 정답

[맥락 및 가정] 원래 요청에 있는 정보(대상, 조건, 숫자)를 빠짐없이 옮기고, 부족한 정보는 "가정: ..."으로 합리적인 기본값을 적는다.

[출력 형식] 답의 구조만 적는다 (예: 표, 목록, 문단 구성, 소제목).
규칙:
1. 원래 요청의 사실·조건·숫자·의도를 바꾸거나 빼지 않는다.
2. 원래 요청에 없는 분량(글자 수·줄 수·개수 제한), 톤·말투, 새로운 사실, 특정 풀이 방법을 만들지 않는다. 원래 요청이 분량이나 톤을 정했으면 그대로 옮긴다.
3. 역할(페르소나, "당신은 ~입니다")을 쓰지 않는다.
4. {{빈칸}}을 쓰지 않는다.
5. 요청에 포함된 긴 글(요약·검토 대상)은 어느 섹션에도 다시 옮기거나 풀어 쓰지 말고 "[원래 요청]의 글"이라고 가리킨다. 원래 요청은 프롬프트 끝에 그대로 붙는다.
6. 이미 구체적인 요청이면 최소한으로만 정리한다.
7. 원래 요청과 같은 언어로 쓴다.

### v4 학습 데이터의 정답(가이드)
너는 '답변 가이드' 작성기다. 사용자의 짧은 요청에 답하지 말고, 다른 AI가 이 요청에 더 좋은 답을 하도록 이 분야를 잘 아는 사람이 짚어 줄 내용을 써라.

- 다룰 내용: 이 요청에만 해당하는 핵심 고려사항 2~4개. 짧은 명사구로.
규칙:
1. 다룰 내용은 이 요청에서만 나오는 구체적인 것이어야 한다. "장단점", "비용", "기능", "정의", "절차", "예시", "주의사항", "사용자 경험"처럼 어떤 요청에나 붙는 말은 그 자체로 쓰지 말고, 무엇의 비용·위험인지 구체적으로 쓴다 (예: "비용" 대신 "보증금 반환 위험", "대출 이자와 월세 부담 비교").
2. 널리 알려지고 확실한 사실에 근거한 고려사항만 쓴다. 불확실한 수치, 날짜, 특정 제품·회사 이름, 사용자 정보(나이, 직업, 상황)는 만들지 않는다.
3. 요청에 이미 있는 조건을 바꾸지 않고, 분량·톤·형식을 정하지 않는다.
4. 요청과 같은 언어로 쓴다.
5. 다음 경우만 가이드가 필요 없다: 정답이 하나로 정해진 계산·수학 문제·퍼즐, 요청 안에 주어진 코드·글·데이터를 처리하는 요청(오류 찾기, 정보 뽑기), 요약·검토할 글이 요청에 없는 요약 요청. 이때는 {"그대로": true}만 출력한다. 개념·정의 질문("~가 뭐야", "~ 설명해줘")이나 코드 작성 요청은 여기에 해당하지 않으니 가이드를 쓴다.
JSON으로만: {"갈림길": "...", "다룰 내용": ["...", "..."]}
### v4 학습 데이터의 정답(다시쓰기)
사용자가 AI에게 보내려는 짧은 <요청>과, 좋은 답을 위해 짚어야 할 <가이드>가 있다.
<요청>을 한 문단의 프롬프트로 다시 써라. 요청에 답하지 마라.
규칙:
1. 원래 요청의 모든 정보(대상, 상황, 조건, 용어, 숫자)를 하나도 빼지 않는다. 원래 요청의 표현을 최대한 그대로 쓰고, 영어 용어는 영어 그대로 둔다.
2. 말투를 원래 요청과 똑같이 맞춘다. 원래 요청이 존댓말이면 모든 문장을 존댓말로, 반말이면 모든 문장을 반말로.
